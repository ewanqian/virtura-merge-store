# MERGE publishing boundary

This repository is the **public product and demonstration layer**, not the operating archive.

| Publish here | Keep in private VIRTURA-Team | Keep in credential storage |
| --- | --- | --- |
| Approved product concepts, source code, public roadmap, public service packages, cleared imagery and factual test summaries | Pricing strategy, unapproved customer briefs, supplier offers and costs, live project management, detailed SKU scoring, raw production approvals | API tokens, OAuth secrets, passwords, production keys and account recovery codes |

Before a public commit: check whether the document contains a real client's names/terms, internal prices, live schedules, confidential attachments or credential material. If so, write to the private project workspace instead, and publish a concise cleared summary if needed. Public templates with blank fields may remain public.

**Existing history:** older Git commits and PR diffs can remain accessible after files disappear from the current branch. Do not force-rewrite history for ordinary commercial notes. Handle confirmed credentials through revocation/rotation first; review any history-removal operation separately.

Private originals from the November 2026 boundary cleanup are preserved under `ewanqian/VIRTURA-Team/projects/virtura-merge-store/internal/` (accessible only to those granted that private repository).
